|---|--------------------|--------------|--------|------------------|
| 1 | Проблеми з пропускною здатністю мережі під час трансляції відео | Висока | Високий | Оптимізувати потік через адаптивний бітрейт, використовувати CDN або буферизацію |

| 5 | Перевантаження сервера при високій кількості одночасних глядачів | Висока | Високий | Масштабування системи, використання кешування, розподіл навантаження |

# План управління проєктом

## 1. **Мета**
Розробити програмно-апаратне рішення для потокової трансляції відео, яке забезпечить стабільне відтворення контенту незалежно від пристрою користувача (ПК, смартфон, планшет).  
Система повинна поєднувати серверну частину, базу даних для зберігання відео-контенту та клієнтський веб-інтерфейс.

## 2. **Команда проєкту** 
- **Back-end розробник/QA інженер** — реалізація API, організація потокової передачі відео, робота з файловою системою/тестування системи на стабільність, навантаження, сумісність.  
- **Front-end розробник/Системний інженер** — створення веб-інтерфейсу плеєра, адаптивного дизайну/налаштування серверів, контейнеризація, CI/CD.   

## 3. **Методологія**
- Метод управління — **Agile/Scrum**.  
- Тривалість спринта — **2 тижні**.  
- Щоденні стендапи (15 хв).  
- Демонстрація результатів і ретроспектива після кожного спринта.  

## 4. **Основні етапи**

**a) Розробка бази даних і структури проєкту**  
   - Проєктування структури зберігання відео та метаданих.  
   - Підготовка середовища для серверної частини.  
   - Налаштування бази даних і тестових даних.  

**b) Розробка бекенд-частини**  
   - Реалізація API для отримання відео, авторизації користувачів.  
   - Підключення WebSocket'у (для синхронізації, передачі метаданих).  
   - Оптимізація передачі даних для стабільного відтворення.  

**c) Розробка інтерфейсу користувача**  
   - Створення веб-плеєра з підтримкою адаптивного відео.  
   - Тестування роботи на різних пристроях.  
   - Інтеграція з бекендом і фінальне UI-налаштування.  

## 5. **Контроль якості**
- Модульне та інтеграційне тестування компонентів.  
- Тестування навантаження серверної частини.  
- Перевірка сумісності відеоплеєра з основними браузерами.  
- Code review усіх ключових частин системи.  

## 6. **Комунікація**
- Основний канал: **Telegram**.  
- Трекінг завдань: **Jira**.  
- Щотижневі короткі звіти про прогрес кожного учасника.  


## 7. **Моніторинг ризиків**
- Щотижневе оновлення матриці ризиків.  
- Пріоритизація ризиків за формулою:  
  **Ризик = Ймовірність × Вплив.**  
- Дії реагування: **уникнення → мінімізація → резервування → прийняття.**  

---

## 8. **Очікуваний результат**
- Система, здатна транслювати відео в режимі реального часу.  
- Можливість перегляду трансляцій з будь-яких пристроїв.  
- Надійне зберігання відео-контенту на сервері.  
- Простий та зручний веб-інтерфейс для користувача.  
- Документована структура проєкту для подальшого масштабування.
