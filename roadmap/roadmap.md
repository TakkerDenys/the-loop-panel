# Дорожня карта проєкту
## 1. Розробка бази даних та skeleton'у проєкту

### Цілі:
• cтворити архітектуру системи (файлова система, базові модулі);  
• спроєктувати базу даних для зберігання інформації про екрани, контент, плейлисти, користувачів та налаштування;  
• налаштувати середовище розробки (Git, Docker, CI/CD, підключення до БД).

### Результати:
• створена структура проєкту (Node.js + React);  
• розгорнута та протестована база даних (PostgreSQL/MongoDB);  
• визначено моделі даних та базові зв’язки (екрани, контент, користувачі);  
• підготовлено початкове API для тестування з’єднання з БД.

### Ризики:
• некоректна модель даних або надмірна складність структури;  
• проблеми зі з’єднанням або налаштуванням Docker/CI;  
• потенційні зміни архітектури під час наступних ітерацій.

## 2. Розробка бекенд частини проєкту

### Цілі:
• реалізувати серверну логіку для роботи з контентом, плейлистами, екранами;  
• налаштувати авторизацію та автентифікацію користувачів (за допомогою JWT токену);  
• реалізувати інтеграції з зовнішніми API (OpenWeather, НБУ);  
• забезпечити синхронізацію контенту у реальному часі (WebSocket).

### Результати:
• працюючий бекенд з основним REST API;  
• підключені зовнішні сервіси (погода, курс валют);  
• реалізована система користувачів та ролей (адмін, оператор);  
• забезпечена синхронізація контенту між сервером та пристроями. 

### Ризики:
• проблеми зі стабільністю зовнішніх API;  
• затримки у відтворенні через перевантаження сервера;  
• уразливості безпеки при роботі з токенами або сокетами.

## 3. Розробка інтерфейсу (адмін-панель + фронтенд плеєр)

### Цілі:
• створити веб-інтерфейс адміністратора для управління контентом, екранами, рекламними блоками;  
• реалізувати медіаплеєр (на фронтенді) для відтворення контенту на екранах;  
• забезпечити адаптивний дизайн (React + Tailwind);  
• провести тестування повного циклу роботи системи.

### Результати:
• повністю функціональна адмін-панель (React);  
• працюючий медіаплеєр, який автоматично оновлює контент;  
• зручний інтерфейс для управління модулями (погода, валюта, реклама);  
• готовність системи до демонстрації або MVP-релізу.

### Ризики:
• недостатня оптимізація продуктивності UI;  
• можливі розсинхронізації між фронтендом і бекендом;  
• проблеми з адаптивністю на різних пристроях.
